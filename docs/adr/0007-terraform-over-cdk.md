# ADR-007: Terraform (not AWS CDK) for infrastructure as code

- **Status:** Accepted, 2026-10-18
- **Deciders:** project author
- **Related:** [04 §10](../04-architecture.md#10-deployment), [06 §4](../06-quality-operations.md#4-infrastructure-as-code-terraform), [ADR-010](0010-lambdas-outside-vpc.md)

## Context

The cost model only works if every cloud resource can be **created and destroyed with one command** and nothing is left behind ([02 cost model](../02-concept-selection.md#cost-model-added-after-budget-discussion)). Staging must be disposable ($0 when torn down), prod must be reproducible after a disaster (RTO < 1 h for infrastructure, [05 §10.5](../05-security-reliability.md#105-backups-and-disaster-recovery)), and the CI pipeline must be able to plan changes on every pull request.

The stack is AWS-only (Lambda, S3, EventBridge Scheduler, API Gateway, CloudFront, CloudWatch, SNS, Budgets, IAM, SSM) plus Neon, which is created once by hand. IaC tools are named in a minority of postings (Terraform/IaC 4 of 18 companies, [02](../02-concept-selection.md)), so recognition matters more than features.

## Decision

- **Terraform ≥ 1.10** with the S3 backend and **`use_lockfile = true`** (native S3 locking; no DynamoDB lock table).
- Layout ([06 §4](../06-quality-operations.md#4-infrastructure-as-code-terraform)):
  - `infra/bootstrap/`: the versioned, encrypted state bucket, created once and never destroyed by `make down`.
  - `infra/modules/`: `storage`, `functions`, `scheduler`, `api`, `edge`, `observability`, `budget`, `iam`, `github_oidc`.
  - `infra/envs/{staging,prod}/`: thin root modules with `terraform.tfvars` (staging has ingestion disabled by default).
- One command each way: `make up ENV=staging` / `make down ENV=staging`. `make down ENV=prod` refuses to run unless `ALLOW_DATA_DESTROY=1` is set, and prod data buckets have `force_destroy = false`.
- **No secrets in state:** SSM parameters are created with the value `unset` and set out of band with the AWS CLI ([contracts §1](../contracts.md#ssm-parameters-securestring-under-ssm_prefix)). One documented exception: `origin_verify_secret`, the `X-Origin-Verify` value CloudFront sends to the API, is generated by Terraform because CloudFront and SSM must receive the same value in one apply. It grants no data access ([ADR-005](0005-api-gateway-http-api-over-function-urls.md)).
- Every resource is tagged `project=stopwatch env=<env> owner=<you> ttl=<date|none>`.
- CI runs `terraform fmt -check`, `validate`, `tflint` and Checkov on every PR and posts `terraform plan` as a PR comment; deploys assume a GitHub OIDC role, never static keys.

## Alternatives considered

| Alternative | Why rejected |
|---|---|
| **AWS CDK (Python)** | Same language as the backend, which is attractive, but it synthesizes to CloudFormation (stack limits, slower rollbacks, a bootstrap stack per account/region) and is less portable and less commonly named than Terraform. |
| **AWS SAM / Serverless Framework** | Good for Lambda + API, weaker for CloudFront, Budgets, OIDC roles and alarms; a second tool would still be needed. |
| **Pulumi** | Real code instead of HCL, but a smaller community and a state backend decision of its own. |
| **OpenTofu** | Compatible and fully open source; a reasonable drop-in. Terraform was chosen for recognition; the configuration should run on either with little or no change. |
| **Console clicks + a checklist** | Not reproducible, cannot be torn down reliably, and cannot be reviewed in a PR. |

## Consequences

**Positive**

- `make up` / `make down` make staging and load-test environments disposable, which is what keeps them at $0.
- `terraform plan` in PRs makes infrastructure changes reviewable; Checkov findings block merges unless an exception is justified inline.
- Native S3 locking removes the DynamoDB lock table.
- Portable skills and a recognizable tool for reviewers.

**Negative**

- HCL instead of Python: a second language in the repo, with its own lint and test tooling.
- Neon lives outside Terraform for now (created in its console; connection strings set in SSM), so a full rebuild has one manual step.
- Emergency CLI changes during an incident (concurrency, throttles, flags) create drift and must be copied back into `terraform.tfvars` afterwards; the runbooks say so.
- Terraform state still contains resource metadata (ARNs, names); the state bucket is private, versioned and encrypted.

## Revisit when

- A team or employer standard is CDK or Pulumi.
- Neon's Terraform provider is mature enough to bring the database project and branches under the same state.
- The stack outgrows a single AWS account (separate accounts per environment would change the root-module layout).
